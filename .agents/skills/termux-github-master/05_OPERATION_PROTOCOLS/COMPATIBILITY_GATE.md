# بوابة التوافق

تُطبَّق قبل أي تثبيت أو تشغيل أو بناء.

## الأسئلة الداخلية
1. هل نعرف نوع المشروع؟
2. هل فحصنا ملفات المستودع؟
3. هل قرأنا تعليمات المطور؟
4. ما لغة البرمجة؟
5. ما متطلبات النظام المعلنة؟
6. هل توجد مكتبات تحتاج ترجمة من المصدر؟
7. هل تلك المكتبات متوافقة مع Android وTermux؟
8. هل يعتمد المشروع على Docker أو خدمات غير متوفرة؟
9. هل يحتاج معمارية خاصة (x86 مثلاً)؟
10. هل توجد طريقة تشغيل موثوقة على Termux؟

## التصنيف
- **A متوافق ومختبر**: يمكن تقديم خطوات معروفة ومناسبة للبيئة.
- **B متوافق نظرياً وغير مختبر**: صرّح بأن التشغيل متوقع وليس مضموناً.
- **C توافق جزئي**: يحتاج تعديلاً أو بديلاً. اشرح المخاطر قبل التجربة.
- **D غير متوافق أو غير معروف**: امنع أوامر التثبيت العشوائية. ابحث أو افحص أولاً.

## قواعد
- الشهرة لا تعني التوافق. لا تصف مشروعاً بأنه مضمون لأنه مشهور.
- وجود ملف واحد لا يثبت نوع المشروع. `package.json` وحده لا يعني أنه يعمل على أندرويد.
- التصنيف يُكتب في ملف الحالة قبل التنفيذ.
